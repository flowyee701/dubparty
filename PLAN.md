# DubParty — план реализации

Браузерная мультиплеерная пати-игра: игроки переозвучивают клипы своим голосом, вместе смотрят результат и голосуют.

Статус: **реализовано**. Интеграция с Twitch (раздел 11, этап 9) исключена по решению заказчика уже после реализации; настройка «Скрыть код комнаты» оставлена. Остальные отступления от плана перечислены в README.

## 2. Ключевые архитектурные решения

1. **Один сервер — один процесс.** Fastify отдаёт REST (загрузки, скачивания, паки, медиа с Range), Socket.IO — реалтайм. В продакшене тот же процесс раздаёт собранный клиент, поэтому деплой — один контейнер и один порт. В dev — Vite с прокси на сервер.
2. **Состояние комнат — в памяти сервера**, паки и учёт файлов — в SQLite. Перезапуск сервера обрывает идущие игры (файлы при этом корректно доочищаются по записям в БД). Горизонтальное масштабирование на несколько инстансов в объём не входит — для пати-игры на 2–8 человек это избыточно.
3. **Сервер — единственный авторитет.** Машина состояний фаз, таймеры, распределение ролей, приём голосов и подсчёт очков живут только на сервере. Клиент получает снапшот состояния и шлёт намерения; каждое событие проходит zod-валидацию и проверку прав (хост/фаза/принадлежность).
4. **Выравнивание озвучки «запекается» на сервере.** Клиент присылает сырой дубль и измеренное смещение начала записи относительно видео. Сервер через ffmpeg приводит дорожку к шкале времени клипа (`t=0` аудио = `t=0` видео), накладывает эффект и собирает один mp4 (видео копируется без перекодирования + музыка + голос). Следствия:
   - при общем просмотре играет **один медиа-элемент**, рассинхрон голоса и картинки внутри него невозможен;
   - файл для просмотра и файл для скачивания — один и тот же, эффект в нём гарантированно одинаков для всех.
5. **Эффекты описаны один раз** в `packages/shared` как набор параметров. Из них строятся и граф Web Audio (предпрослушивание до отправки), и цепочка фильтров ffmpeg (итог). Честная оговорка: совпадение — на слух и по параметрам, но не побитовое: алгоритмы сдвига высоты тона в браузере и в ffmpeg разные.
6. **Запись — два бэкенда.** Основной — `MediaRecorder` (webm/opus или mp4/aac, выбор через `isTypeSupported`). Запасной — захват PCM через AudioWorklet в WAV, если `MediaRecorder` недоступен. Сервер принимает всё и конвертирует в единый формат.

## 3. Стек

- **Монорепо:** pnpm workspaces — `apps/client`, `apps/server`, `packages/shared`. TypeScript `strict` (+ `noUncheckedIndexedAccess`) везде.
- **Клиент:** React, Vite, Tailwind, Zustand, i18next (ru по умолчанию, en), socket.io-client.
- **Сервер:** Fastify, Socket.IO, zod, pino, Drizzle ORM + SQLite (`better-sqlite3`), fluent-ffmpeg, `@fastify/multipart`, `@fastify/rate-limit`, `file-type`, `archiver`/`yauzl` (zip), `tmi.js`, `@aws-sdk/client-s3`.
- **Тесты и качество:** Vitest, Playwright (Chromium + WebKit), ESLint, Prettier.
- **Продакшен:** многоступенчатый Dockerfile (Node 24 LTS + системный ffmpeg), docker-compose с томами для `storage/` и БД.

## 5. Модель данных

### SQLite (Drizzle)

- `packs` — `id, title, description, author, language, license, builtin, owner_token_hash, created_at, updated_at`
- `clips` — `id, pack_id, position, title, video_key, poster_key, music_key?, duration_ms, width, height, characters (json), lines (json), attribution`
- `room_files` — `id, room_code, kind, storage_key, size, created_at` — учёт файлов комнаты для лимитов и очистки
- `rooms_ended` — `room_code, ended_at` — чтобы очистка пережила перезапуск

### В памяти сервера

```
Room { code, hostId, players[], settings, phase, phaseEndsAt, game?, twitch?, createdAt, endedAt? }
Player { id, sessionTokenHash, nickname, avatar, color, connected, socketId?, score }
Settings { mode: parallel|roles|free, rounds 1–10, recordSeconds 30–180, packId, effectsEnabled, hideCode }
Game { roundIndex, rounds[] }
Round { clipId, assignments (роли/труппы), takes{playerId→Take}, entries[], playback, votes, audienceVotes, scores }
Take { status: uploaded|processing|ready|failed, offsetMs, effect, mime, keys }
Entry { id, authorIds[], reviewKey }   // то, что смотрят и за что голосуют
```

### Формат пака (`pack.json`, zod-схема в `packages/shared`)

```jsonc
{
  "formatVersion": 1,
  "id": "demo",
  "title": "Демо-пак",
  "description": "...", "author": "...", "language": "ru", "license": "CC0-1.0",
  "clips": [{
    "id": "robots-argue",
    "title": "Спор роботов",
    "video": "clips/robots-argue/video.mp4",

    "characters": [{ "id": "a", "name": "Бип", "color": "#f59e0b" }],

Архив `.zip` = `pack.json` + файлы, на которые он ссылается. При импорте — защита от zip-slip, лимиты на число и размер файлов, повторная проверка каждого видео.

### Хранилище

`StorageAdapter { put, getStream(range), getLocalPath, delete, deletePrefix, exists, stat }` — реализации для локального диска и S3-совместимого хранилища (для ffmpeg файл из S3 скачивается во временный).

```

## 6. Протокол

Все события client→server — с ack: `{ ok: true, data } | { ok: false, error: { code, message } }`. Полезная нагрузка валидируется zod, на сокет действует ограничитель частоты (token bucket) и лимит размера сообщения.

### Client → Server (Socket.IO)

| Событие                | Данные                                   | Кто / когда              |
| ---------------------- | ---------------------------------------- | ------------------------ |
| `room:create`          | `nickname, avatar, color`                | любой                    |
| `room:join`            | `roomCode, nickname, avatar, color`      | любой, фаза lobby        |
| `session:resume`       | `sessionToken`                           | переподключение          |
| `room:leave`           | —                                        | игрок                    |
| `player:update`        | `nickname?, avatar?, color?`             | игрок, lobby             |
| `lobby:updateSettings` | частичные настройки                      | хост, lobby              |
| `lobby:kick`           | `playerId`                               | хост                     |
| `lobby:transferHost`   | `playerId`                               | хост                     |
| `game:start`           | —                                        | хост, ≥2 игроков         |
| `round:clipReady`      | —                                        | игрок, клип предзагружен |
| `playback:control`     | `action: play/pause/seek/next/prev, positionMs?` | хост, playback   |
| `vote:cast`            | `category, entryId`                      | игрок, voting            |
| `phase:continue`       | —                                        | хост, results            |
| `game:restart`         | —                                        | хост, final              |
| `twitch:connect` / `twitch:disconnect` | `channel`                | хост                     |
| `time:sync`            | `clientTime` → `serverTime`              | любой                    |

### Server → Client

| Событие         | Данные                                                                    |
| --------------- | ------------------------------------------------------------------------- |
| `room:state`    | полный персонализированный снапшот комнаты (чужие голоса до конца фазы скрыты) |
| `playback:sync` | `entryIndex, playing, positionMs, serverTime, rev`                        |
| `take:status`   | прогресс обработки дубля                                                  |
| `room:kicked`, `room:closed` | причина                                                      |
| `twitch:status` | состояние подключения, счётчик голосов зрителей                           |

### HTTP

- `POST /api/rooms/:code/rounds/:n/take` — загрузка дубля (multipart; авторизация токеном сессии; повторная загрузка до конца таймера заменяет предыдущую)
- `GET /api/media/*` — видео/постеры/ревью с поддержкой Range
- `GET /api/rooms/:code/rounds/:n/export/:entryId` — mp4 своей озвучки; `.../export-all` — zip всех озвучек (только хост)
- `GET/POST/PUT/DELETE /api/packs…`, `POST /api/packs/:id/clips` (загрузка видео), `POST /api/packs/import`, `GET /api/packs/:id/export`
- `GET /healthz`

## 7. Игровая логика

**Фазы:** `lobby → intro → recording → processing → playback → voting → results → (следующий раунд | final)`.

- Каждая фаза имеет серверный таймер; `recording` заканчивается досрочно, когда отправили все; `processing` ждёт сборки файлов (с верхним пределом; упавший дубль исключается из просмотра, игрок видит причину).
- Отключившийся игрок остаётся в комнате и может вернуться по токену; если отключился хост — права переходят следующему подключённому. Игрок, не вернувшийся за отведённое время в lobby, удаляется.

**Режимы:**

- **Parallel** — один клип всем, каждый озвучивает целиком; субтитры-подсказки включены. Одна запись = один `entry`.
- **Free** — то же, но без субтитров.
- **Roles** — игроки делятся на труппы, в труппе персонажи распределяются по кругу (если игроков меньше, чем персонажей, — игрок получает несколько ролей). Каждый записывает проход клипа со своими подсвеченными репликами; сервер вырезает окна реплик по таймкодам (с небольшим запасом и фейдами) и сводит труппу в одну дорожку. Одна труппа = один `entry`. Если труппа всего одна — голосуют за отдельных участников внутри неё.

**Голосование:** категории «самый смешной» и «лучшая актёрская игра»; нельзя голосовать за `entry`, где ты автор; один голос на категорию, до конца таймера можно поменять.

**Очки:** +100 за каждый полученный голос; +50 победителю категории (при ничьей — всем лидерам); +25 за то, что проголосовал в обеих категориях; +100 фавориту зрителей Twitch (отдельная категория, на основные не влияет). В трупповых `entry` очки получают все авторы. Формулы — чистые функции в `shared/scoring.ts`, покрыты юнит-тестами.

## 8. Синхронизация — самая рискованная часть

### Запись

1. Перед отсчётом видео предзагружено и «разогрето» (на iOS — разблокировано жестом пользователя), микрофонный поток и рекордер созданы заранее.
2. По окончании отсчёта 3-2-1 в одном обработчике вызываются `recorder.start()` и `video.play()`.
3. Смещение измеряется, а не предполагается: момент фактического старта записи (событие `start` рекордера / время первого блока PCM) сопоставляется с временем видео через `requestVideoFrameCallback` (`mediaTime` ↔ `performance.now()`), с запасным вариантом по `currentTime`. К нему добавляется компенсация входной задержки (`track.getSettings().latency`, `AudioContext.baseLatency`).
4. Во время записи раз в 250 мс проверяется дрейф видео относительно часов записи; при превышении порога корректируется `currentTime`.
5. При предпрослушивании дубль играет через Web Audio, а видео подгоняется к аудио-часам той же процедурой (мягко — `playbackRate`, грубо — `currentTime`).

### Общий просмотр

- Клиент оценивает сдвиг часов относительно сервера по серии `time:sync` (берётся замер с минимальным RTT).
- Сервер хранит `{entryIndex, playing, positionMs, serverTime}`; клиент вычисляет целевую позицию и держит отклонение **≤150 мс**: малое — подстройкой `playbackRate`, большое — прыжком `currentTime`.
- Пауза, перемотка, следующий/предыдущий — только от хоста, через сервер.

### Проверка

- Юнит-тесты на математику часов и дрейфа.
- Автотест (Playwright): калибровочный клип с щелчками в известные моменты; в качестве «микрофона» в запись заворачивается звук самого клипа; после серверной обработки в готовой дорожке находятся щелчки и сверяются с эталоном — порог ошибки ±50 мс.
- Ручная проверка на живом микрофоне на этапе 3.

## 9. Голосовые эффекты

`pitchUp`, `pitchDown`, `robot`, `echo`, `radio`, `helium` (+ «без эффекта»).

| Эффект    | Web Audio (предпрослушивание)                         | ffmpeg (итог)                                  |
| --------- | ----------------------------------------------------- | ---------------------------------------------- |
| pitch ±   | AudioWorklet — гранулярный сдвиг высоты без смены длительности | `asetrate` + `aresample` + `atempo`   |
| helium    | больший сдвиг вверх + подъём верхних частот           | то же + `equalizer`                            |
| robot     | кольцевая модуляция (осциллятор → gain)               | `amultiply` с `sine`                           |
| echo      | `DelayNode` с обратной связью                         | `aecho`                                        |
| radio     | полосовой фильтр 300–3400 Гц + перегруз + шум         | `highpass`/`lowpass` + `acrusher`/`asoftclip` + шум |

Длительность дорожки эффекты не меняют — иначе сломалась бы синхронизация.

## 10. Паки

- **Демо-пак** (4 клипа, CC0): генерируется скриптом — кадры рисуются на canvas (`@napi-rs/canvas`), собираются в видео через ffmpeg, музыка синтезируется. Простые персонажи с анимацией «рта» по таймкодам реплик, чтобы было под что попадать. Один клип — калибровочный для теста синхронизации. Готовые файлы лежат в репозитории, скрипт остаётся для воспроизводимости.
- **Редактор:** загрузка видео (≤60 с, ≤100 МБ), обрезка на таймлайне, персонажи, реплики с таймкодами (перетаскивание границ + привязка к текущему времени), превью с подсветкой субтитров, импорт/экспорт zip.
- **Права:** аккаунтов нет, поэтому пак редактирует тот, у кого токен владельца (выдаётся при создании, хранится в localStorage). Встроенный пак только для чтения.
- **Валидация загрузок:** сигнатура файла (`file-type`), затем `ffprobe` (реальная длительность, наличие видеодорожки), лимиты размера; на комнату — лимит числа и суммарного объёма файлов.
- **Нормализация:** H.264 yuv420p ≤720p 30 fps, ключевой кадр каждую секунду, `+faststart`, оригинальный звук удаляется; постер — jpg.

## 11. Twitch и режим стримера

- Хост вводит имя канала; сервер анонимно подключается через tmi.js на время игры.
- Во время голосования команды `!1`, `!2`… — один голос на зрителя (учитывается последний). Итог — отдельная категория «выбор зрителей».
- «Скрыть код комнаты»: код и ссылка замаскированы, копирование работает, показ — по удержанию.

## 12. Надёжность и безопасность

- zod на каждое событие и каждый HTTP-запрос; проверка прав и фазы до любого изменения состояния.
- Ограничение частоты: события сокета — per-socket, HTTP — `@fastify/rate-limit`; `maxHttpBufferSize` у Socket.IO; лимиты multipart.
- Токен сессии — случайные 256 бит, на сервере хранится хэш.
- Имена файлов из пользовательского ввода в пути не попадают; ключи хранилища генерирует сервер.
- Очистка: комната и её файлы удаляются через `ROOM_TTL_HOURS` после конца игры и через `ROOM_IDLE_HOURS` бездействия.
- pino-логи, общий обработчик ошибок, изоляция сбоев ffmpeg (упавший дубль не роняет раунд), graceful shutdown (остановка приёма, уведомление комнат, закрытие БД).
- Конфигурация через `.env`, валидируется zod при старте; `.env.example` в репозитории.

## 13. UI/UX

- Тёмная и светлая темы (по системной, с переключателем), адаптив: телефон — игрок, ноутбук — хост.
- Анимации переходов фаз и звуки интерфейса (синтезируются Web Audio, отключаемы), уважение `prefers-reduced-motion`.
- Доступность: видимый фокус, aria-метки, live-регионы для таймеров и смены фаз, контраст AA, управление с клавиатуры.
- Онбординг: «Как играть» и проверка микрофона (выбор устройства, индикатор уровня, пробная запись) перед первой игрой.
- Понятные сообщения: отказ в доступе к микрофону, нет устройства, небезопасный контекст (нужен HTTPS), автозапуск звука заблокирован.

1. **Каркас** — монорепо, shared-типы и схемы, конфиги, скрипты CI, Dockerfile/compose, healthcheck.
2. **Лобби** — комнаты, коды, ники/аватары, настройки, кик, передача хоста, переподключение.
3. **Клип + запись** — плеер, отсчёт, рекордер (оба бэкенда), измерение смещения, предпрослушивание, проверка микрофона; тест синхронизации.
4. **Раунд Parallel** — машина фаз, загрузка дублей, серверная обработка, синхронный просмотр.
5. **Голосование и очки** — категории, таймер, таблица лидеров, подиум.
6. **Roles и Free** — труппы, распределение ролей, сведение по таймкодам.
7. **Эффекты и экспорт** — 6 эффектов в Web Audio и ffmpeg, скачивание mp4 и zip.
8. **Паки** — генератор демо-пака, редактор, импорт/экспорт.
9. **Twitch** — чат, голоса зрителей, скрытие кода.
10. **Полировка** — темы, анимации, звуки, i18n, доступность, e2e на 3 игроков (Chromium + WebKit), README со скриншотами, инструкции Fly.io / Render / Cloudflare Tunnel.

## 15. Риски и что сделаю, если они сработают

| Риск | План |
| ---- | ---- |
| `better-sqlite3` не соберётся под Node 26 | Перейти на `@libsql/client` (у Drizzle есть драйвер), схема не меняется. |
| В `ffmpeg-static` нет нужного фильтра | Все фильтры выбраны из базового набора; проверю на этапе 1 списком `-filters`, при нехватке заменю эквивалентом. |
| WebKit в Playwright не поддерживает флаги фейкового микрофона Chromium и может не иметь `MediaRecorder` | В WebKit-тесте `getUserMedia` подменяется потоком из Web Audio; при отсутствии `MediaRecorder` сработает WAV-бэкенд. Если полный цикл в WebKit всё равно не пройдёт — скажу прямо, что именно не работает и почему. |
| iOS Safari: автозапуск звука, особенности `MediaRecorder` | Разблокировка звука жестом, mp4/aac, WAV-бэкенд как запасной. Проверить на реальном iPhone я не могу — только в WebKit и симуляторе; это останется за вами. |
| `fluent-ffmpeg` заархивирован автором | Работает; использую, как указано в задаче, за тонкой обёрткой — заменить на прямой вызов ffmpeg можно будет без правок остального кода. |
| Точность `MediaRecorder` на старте записи плавает между браузерами | Смещение измеряется по факту; калибровочный тест покажет реальную ошибку. Если она выйдет за порог в каком-то браузере — для него по умолчанию включится WAV-бэкенд с посэмпловым временем. |

## 16. Что в объём не входит

- Аккаунты и регистрация, модерация контента.
- Несколько инстансов сервера и общее состояние между ними.
- Сам деплой в облако: будут конфиги и инструкции, а выкладывать — только по отдельной просьбе.
